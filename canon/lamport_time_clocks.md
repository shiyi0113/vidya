# 时间、时钟，以及分布式系统中事件的顺序

**Leslie Lamport · Massachusetts Computer Associates, Inc.**
*Communications of the ACM · 1978年7月*

> **摘要**：本文考察分布式系统中"一个事件**先于**另一事件发生"这一概念，并表明它定义了系统中事件的一种**偏序**。本文给出一种用于同步**逻辑时钟**的分布式算法——这种逻辑时钟可被用来给事件加上**全序**。本文用一个解决同步问题的方法来说明这一全序的应用。随后该算法被特化为同步**物理时钟**，并推导出物理时钟之间不同步程度的一个上界。
>
> **关键词与短语**：分布式系统、计算机网络、时钟同步、多进程系统
> **CR 类别**：4.32, 5.29

## 引言

时间这一概念是我们思考方式的基本元素。它派生于一个更基本的概念——**事件发生的顺序**。我们说"某事在 3:15 发生"，意思是它在我们的时钟读 3:15 之后、读 3:16 之前发生。**事件时间顺序的概念渗透于我们对系统的思考**。例如，在一个航班订座系统中，我们规定"如果订座请求在该班次满员**之前**做出，则应被批准"。然而我们将看到：在分布式系统中考虑事件时，这一概念必须被仔细重新审视。

一个**分布式系统**由一组在空间上分隔的不同进程构成，它们之间通过交换**消息**通信。一组互联的计算机网络（如 ARPA net）就是一种分布式系统。**单台计算机也可被视为分布式系统**——其中央控制单元、内存单元、I/O 通道是分立进程。一个系统是**分布式**的，当**消息传输延迟相对于单进程内事件之间的时间不可忽略**时。

我们主要关心**空间上分隔的计算机系统**。但许多论述适用范围更广——尤其是单计算机上的多处理系统也涉及与分布式系统类似的问题，因为某些事件可能以不可预测的顺序发生。

在分布式系统中，**有时无法说"两个事件中哪一个先发生"**。"happened before"（先于发生）这一关系因此只是事件的**偏序**。我们发现：问题往往源于人们没有充分意识到这一事实及其推论。

本文中我们讨论由"happened before"关系定义的偏序，并给出一种**将其扩展为全部事件的一致全序**的分布式算法。这一算法可以为分布式系统的实现提供有用的机制。我们用一个解决同步问题的简单方法来说明它的用法。**如果由该算法获得的顺序与用户感知到的顺序不一致，则会出现意外异常的行为**——这可以通过引入**真实物理时钟**来避免。我们描述一种简单的物理时钟同步方法，并推导其失同步程度的上界。

## 偏序

多数人会说："事件 a 在事件 b 之前发生"，意思是 a 在比 b 更早的某个**时刻**发生。他们会用"时间的物理理论"为此定义辩护。然而，**如果一个系统要正确地满足某个规约，那么该规约必须以系统内可观察事件的方式给出**。如果规约用物理时间表示，则系统必须含有真实时钟；即便它含有真实时钟，仍存在"这种时钟并非完美准确，并不严格按物理时间走"的问题。**因此我们将不使用物理时钟来定义"happened before"关系**。

我们先把系统说得更精确。我们假设系统由一组**进程**构成；每个进程由一个**事件序列**构成。视应用而定：在计算机上执行一段子程序可以是一个事件，或者执行一条机器指令可以是一个事件。我们假设进程的事件构成一个序列：在该序列中 a 在 b 之前出现，意味着 a 在 b 之前发生。换言之，**单个进程被定义为带有先验全序的事件集合**。这似乎是"进程"通常的含义。我们的定义可以平凡地扩展到允许进程分裂为不同子进程，但本文不作此扩展。

我们假设**发送或接收一个消息是进程中的一个事件**。然后我们把"happened before"关系（记为 `→`）定义如下：

> **定义。** 系统事件集合上的关系 `→` 是满足以下三条的最小关系：
>
> 1. 若 a 与 b 是同一进程中的事件且 a 在 b 之前出现，则 `a → b`。
> 2. 若 a 是某进程发送某消息这一事件，b 是另一进程接收该消息这一事件，则 `a → b`。
> 3. 若 `a → b` 且 `b → c`，则 `a → c`。
>
> 若两个不同事件 a 与 b 满足 `a ↛ b` 且 `b ↛ a`，则称之为**并发**（concurrent）。

我们假设对任意事件 a 都有 `a ↛ a`（"事件能在其自身之前发生"的系统在物理上似乎并无意义）——这意味着 `→` 是系统所有事件集合上的**反自反偏序**。

可以借助**时空图**（space-time diagram，如**图 1**）来理解此定义：水平方向代表空间，垂直方向代表时间——较晚的时刻在上。点表示事件，垂直线表示进程，**波浪线**表示消息¹。容易看出 `a → b` 意味着可以**沿着进程线与消息线在图中向前移动**从 a 到达 b。例如图 1 中有 `p₁ → r₄`。

> ¹ 何为一个"事件"会影响进程内事件的顺序。例如，"接收一条消息"既可指设置中断位，也可指执行处理该中断的子程序。由于中断不必按发生顺序处理，**这一选择会影响某进程"接收消息事件"的顺序**。
>
> ² 注意消息可能乱序到达。我们允许"发送多条消息"是单个事件，但为方便起见我们假设"接收一条消息"不与任何另一条消息的发送或接收同时发生。

另一种看法是：`a → b` 意味着事件 a **可能因果性地**影响事件 b。**两个事件并发**——意味着两者不能因果性地影响对方。例如图 1 中 p₃ 与 q₃ 是并发的：尽管图被画成 q₃ 在物理时刻上早于 p₃，但**进程 P 在 p₄ 接收到消息之前无法知道 Q 在 q₃ 做了什么**——在 p₄ 之前，P 至多知道 Q **打算**在 q₃ 做什么。

熟悉狭义相对论时空"不变量"表述的读者会觉得这一定义十分自然。在相对论中，事件的顺序也是用"可能发送的消息"来定义的；不过我们采取了**更务实的取径**：只考虑"实际上被发送的消息"。我们应当能够仅凭"实际发生的事件"判断系统是否表现正确——而不需要知道"还可能发生过什么事件"。

## 逻辑时钟

我们现在为系统引入**时钟**。先从抽象视角开始：**时钟**只是给事件赋一个数字的方式——这数字被理解为该事件发生的**时刻**。更精确地：对每个进程 Pᵢ 我们定义一个时钟 `Cᵢ`，它是一个把数字 `Cᵢ(a)` 赋给该进程中任意事件 a 的函数。**整个时钟系统**由函数 `C` 表示——若 b 是进程 Pⱼ 中的事件，则 `C(b) = Cⱼ(b)`。**目前**我们对 `Cᵢ(a)` 与物理时间的关系不做任何假设——所以 `Cᵢ` 是**逻辑时钟**而非物理时钟。它们可以由没有任何实际计时机制的计数器实现。

那么这种时钟系统**正确**意味着什么？我们不能基于物理时间来定义其正确——那要求引入物理时钟。我们的定义必须基于事件发生的顺序。**最强的合理条件是**：若事件 a 在事件 b 之前发生，则 a 应在更早的时刻发生。形式地：

> **时钟条件（Clock Condition）。** 对任意事件 a, b：**若 `a → b`，则 `C(a) < C(b)`。**

注意我们不能要求逆条件成立——那会意味着任意两个并发事件**必须**在同一时刻发生。例如图 1 中 p₂ 与 p₃ 都与 q₃ 并发；如果要求逆条件成立，将意味着两者都必须与 q₃ 同时发生——这与时钟条件矛盾，因为 `p₂ → p₃`。

由 "→" 的定义易知：若以下两条成立，则时钟条件成立：

> **C1.** 若 a, b 是进程 Pᵢ 的事件且 a 在 b 之前，则 `Cᵢ(a) < Cᵢ(b)`。
> **C2.** 若 a 是 Pᵢ 发送某消息这一事件，b 是 Pⱼ 接收该消息这一事件，则 `Cᵢ(a) < Cⱼ(b)`。

让我们用时空图来思考时钟。我们设想一个进程的时钟"在每个数字上敲一下"——这些"敲击"在该进程的事件之间发生。例如若 a, b 是 Pᵢ 中相邻事件、`Cᵢ(a) = 4`、`Cᵢ(b) = 7`，则两事件之间发生敲击 5、6、7。我们把不同进程上"同号敲击"用一条**虚线（tick line）**连起来。这样图 1 的时空图可能给出**图 2**的样子。**C1 意味着进程线上任意两事件之间必须有一条 tick line**；**C2 意味着每条消息线必须穿过一条 tick line**。从 "→" 的图示含义上易见，**这两条恰恰蕴含时钟条件**。

我们可以把这些 tick line 看作时空中某种笛卡尔坐标系的"时间坐标线"。把图 2 的坐标线拉直就得到**图 3**——它是图 2 同一事件系统的另一种合法表示。在不引入物理时间（那需要物理时钟）的情况下，**没有办法决定哪一种表示更"好"**。

读者可以试着把进程组想象成一个二维空间网络——这样时空图变成三维。进程与消息仍是线，**tick line 变成二维曲面**。

现在假设进程是算法、事件代表执行中的某些动作。我们将展示如何向进程引入满足时钟条件的时钟。进程 Pᵢ 的时钟由寄存器 `Cᵢ` 表示——`Cᵢ(a)` 是事件 a 发生时寄存器的值。**`Cᵢ` 在事件之间会改变，但这种改变本身不构成事件**。

为了让时钟系统满足时钟条件，我们要让它满足 C1 与 C2。**C1 简单**——进程只需遵守如下实现规则：

> **IR1.** 每个进程 Pᵢ 在任意两个相邻事件之间递增 `Cᵢ`。

为满足 **C2**，我们要求每条消息 m 携带一个**时间戳** `Tₘ`——它等于消息发送时的时刻；**接收到带时戳 `Tₘ` 的消息时，进程必须把自己的时钟拨到比 `Tₘ` 晚**。更精确地：

> **IR2.**
> (a) 若事件 a 是进程 Pᵢ 发送消息 m，则 m 含时间戳 `Tₘ = Cᵢ(a)`。
> (b) 收到消息 m 时，进程 Pⱼ 把 `Cⱼ` 设为不小于其当前值且大于 `Tₘ` 的某值。

在 IR2(b) 中，我们认为"接收消息事件"在"`Cⱼ` 被重置之后"发生（这只是记号上的一点小烦恼，与任何实际实现无关）。显然 IR2 保证 C2 成立。**因此简单实现规则 IR1 与 IR2 蕴含时钟条件**——它们保证一个正确的逻辑时钟系统。

## 把事件全序化

我们可以用满足时钟条件的时钟系统给系统全部事件加上**全序**。简单地按时间为事件排序；为打破并列，使用进程的任意全序 `≺`。更精确地，定义关系 `⇒`：若 a 是 Pᵢ 中事件、b 是 Pⱼ 中事件，则 `a ⇒ b` 当且仅当：(i) `Cᵢ(a) < Cⱼ(b)`，或 (ii) `Cᵢ(a) = Cⱼ(b)` 且 `Pᵢ ≺ Pⱼ`。容易看出这定义了一个全序，**且时钟条件意味着若 `a → b` 则 `a ⇒ b`**。换言之，关系 `⇒` 是把"happened before"偏序补完为全序的方式之一。³

³ 序 `≺` 在进程间确立了一种优先。如果想要"更公平"的方法，可以让 `≺` 成为时钟值的函数。例如：若 `Cᵢ(a) = Cⱼ(b)` 且 `j < i`，则可以令 `a ⇒ b` 当 `j ≤ Cᵢ(a) mod N ≤ i`，否则 `b ⇒ a`，其中 N 为进程总数。

**这个全序依赖于时钟系统 `Cᵢ`，并不唯一**。不同的、满足时钟条件的时钟选择会得到不同的 `⇒`。给定任何扩展了 `→` 的全序 `⇒`，都存在满足时钟条件的时钟系统得出该序。**只有偏序 `→` 由事件系统唯一决定**。

能把事件全序化对实现分布式系统极有用。事实上，**实现一个正确的逻辑时钟系统的目的就是为了得到这种全序**。我们用解决以下版本的**互斥问题**来说明该全序的用法。

设系统由一组固定进程构成，它们共享一个资源。一次只能由一个进程使用该资源——所以进程必须自我同步以避免冲突。我们希望找到一个把资源**授予某进程**的算法，满足：

- (I) 已被授予资源的进程必须先**释放**它，然后才能再被授予给另一进程。
- (II) 对资源的不同请求必须**按其发出顺序**被批准。
- (III) 若每个被授予资源的进程最终都释放它，则每个请求最终都将被批准。

我们假设资源最初恰好被授予一个进程。

这些是非常自然的要求——它们精确刻画了"解的正确性"⁴。注意条件涉及**事件顺序**：条件 II **没说**对两个并发请求该先批哪一个。

⁴ "最终"这个词应该被精确化，但展开会偏离主题。

请认识到：**这是一个非平凡问题**。使用一个"按收到顺序批"的中央调度进程**行不通**——除非加上额外假设。可以这样看：令 P₀ 为调度进程；假设 P₁ 向 P₀ 发请求，再向 P₂ 发消息；P₂ 收到后向 P₀ 发请求。**P₂ 的请求可能比 P₁ 的更早到达 P₀**。如果 P₂ 的请求先批，条件 II 就被违反了。

为解决这一问题，我们用 IR1 与 IR2 实现一个时钟系统，并用它定义所有事件的全序 `⇒`。这就给出了所有"请求/释放"操作的全序。**有了这一全序，找解就成了一道直观的练习**——只要保证每个进程**得知其他所有进程的操作**即可。

为简化问题，我们做一些（非必需但避开杂细的）假设。**首先**：对任意两个进程 Pᵢ、Pⱼ，从 Pᵢ 发往 Pⱼ 的消息**按发送顺序被接收**；**而且每条消息最终被收到**。（这些假设可以通过引入消息编号与确认协议来去除。）我们也假设每个进程能向其他每个进程**直接**发送消息。

每个进程维护自己的"请求队列"（其他进程看不到）。我们假设请求队列里**最初有一条消息** `T₀: P₀ requests resource`，其中 P₀ 是最初被授予资源的进程，`T₀` 小于任何时钟的初值。

算法由以下五条规则定义。为方便，每条规则定义的动作被认为构成一个事件。

1. **请求资源时**，Pᵢ 把消息 `Tₘ: Pᵢ requests resource` 发送给所有其他进程，并把该消息放入自己的请求队列；其中 `Tₘ` 是该消息的时间戳。
2. 当 Pⱼ 收到 `Tₘ: Pᵢ requests resource` 时，把它放入自己的请求队列，**并向 Pᵢ 发送一条带时间戳的确认消息**。⁵
3. **释放资源时**，Pᵢ 从自己的请求队列里删除任何 `Tₘ: Pᵢ requests resource` 消息，并向所有其他进程发送一条带时间戳的 `Pᵢ releases resource` 消息。
4. 当 Pⱼ 收到 `Pᵢ releases resource` 时，从自己的请求队列里删除任何 `Tₘ: Pᵢ requests resource` 消息。
5. **当下面两条同时满足时，资源被授予 Pᵢ：**
   (i) 它的请求队列里有一条 `Tₘ: Pᵢ requests resource`，按 `⇒` 排在队列里所有其他请求之前（要为消息定义 `⇒`，我们把"消息"等同于"它的发送事件"）。
   (ii) **Pᵢ 已从其他每个进程收到了一条时间戳晚于 `Tₘ` 的消息**。⁶

⁵ 如果 Pⱼ 已经向 Pᵢ 发送过时间戳晚于 `Tₘ` 的消息，则不需要再发确认消息。
⁶ 若 Pᵢ ≺ Pⱼ，则只需 Pᵢ 已从 Pⱼ 收到一条时间戳 ≥ `Tₘ` 的消息。

注意规则 5 的 (i) 与 (ii) 都由 Pᵢ **本地检查**。

容易验证由此定义的算法满足条件 I–III。首先，规则 5 的 (ii) 加上"消息按序到达"的假设，**保证 Pᵢ 已得知所有早于其当前请求的请求**。由于规则 3、4 是仅有的从请求队列删除消息的规则，**容易看出条件 I 成立**。条件 II 由"`⇒` 扩展了 `→`"这一事实推出。规则 2 保证：在 Pᵢ 请求资源后，规则 5 (ii) 最终会满足；规则 3、4 蕴含：若每个被授予资源的进程都最终释放，则规则 5 (i) 最终会满足，**故条件 III 成立**。

**这是一个分布式算法。** 每个进程独立遵守这些规则——**没有中央同步进程或中央存储**。

这一思路可被推广，以实现分布式多进程系统所需的任意同步：把同步规约成一台**状态机**——它由可能命令集 `C`、可能状态集 `S`、与函数 `e: C × S → S` 组成。`e(C, S) = S'` 即"在状态 S 下执行命令 C 让机器转到 S'"。在我们这例中，`C` 由"Pᵢ requests resource"和"Pᵢ releases resource"构成，状态是等待请求队列——队首的请求是当前被授予的请求。执行一条 request 把它加到队尾、执行一条 release 把它从队列中删去⁷。

⁷ 若进程不严格交替 request 与 release，则一条 release 可能从队列里删去 0 条、1 条或多条 request。

**每个进程都独立地模拟该状态机的执行**——使用所有进程发出的命令。**同步之所以达成**：因为所有进程都按时间戳（用 `⇒`）排序命令，所以每个进程都使用**同一序列**的命令。当某进程已知**所有其他进程发出的、时间戳 ≤ T 的命令**时，它就可以执行时间戳为 T 的那条命令。其精确算法是直白的，这里不再赘述。

这种方法允许我们在分布式系统中实现任何想要的多进程同步形式。但所得算法**要求所有进程的主动参与**——每个进程必须知道其他每个进程发出的所有命令；**单个进程的失败会让其他任何进程都无法执行状态机命令，整个系统挂起**。

故障是难题，本文范围之外。我们仅指出：**"故障"这一概念只在物理时间语境下才有意义**——没有物理时间，一个失败的进程与一个仅在事件之间停顿的进程是无法区分的。**用户只能因等待响应过久才能判断"系统挂了"**。一种"即便单个进程或通信线路故障仍可工作"的方法见 [3]。

## 异常行为

我们的资源调度算法按全序 `⇒` 来排序请求。这允许如下"异常行为"：考虑一个全国互联的计算机系统。设某人在计算机 A 上发出请求 A，然后**用电话**让另一城市的朋友在计算机 B 上发出请求 B。**完全可能 B 的时间戳更小、被排在 A 之前**。这是因为系统**无法知道 A 实际上先于 B**——这一先后信息基于系统**外部**的消息。

让我们更细看问题源头。设 𝒮 是所有系统事件的集合；引入更大事件集 𝒮̃，它在 𝒮 之上加上所有相关的"外部事件"（如本例中的电话）。设 ⇝ 是 𝒮̃ 上的"happened before"关系。在我们的例子里 `A ⇝ B` 但 `A ↛ B`。**显然，任何只基于 𝒮 中事件、且不与 𝒮̃ 中其他事件以任何方式关联的算法，都不能保证 A 被排在 B 之前**。

避免这种异常行为有两种方法：

**第一种**——把关于 ⇝ 的必要信息**显式引入系统**。例如：发出请求 A 的人可以从系统拿到该请求的时间戳 `T_A`；发出请求 B 时，朋友可以指定 B 的时间戳要晚于 `T_A`。**这把"避免异常行为的责任交给用户"**。

**第二种**——构造一个满足如下条件的时钟系统：

> **强时钟条件（Strong Clock Condition）。** 对 𝒮̃ 中任意事件 a, b：**若 `a ⇝ b`，则 `C(a) < C(b)`。**

这比普通的时钟条件**更强**——因为 ⇝ 是比 → 更强的关系。**普通的逻辑时钟一般不满足它**。

把 𝒮̃ 等同于物理时空中的一组"真实"事件，并把 ⇝ 视为狭义相对论定义的偏序——**宇宙的奥秘之一是：可以构造彼此独立运行、却满足强时钟条件的物理时钟系统**。所以我们可以用物理时钟来消除异常行为。下面我们转向这种时钟。

## 物理时钟

向时空图引入物理时间坐标，令 `Cᵢ(t)` 表示物理时刻 t 时时钟 `Cᵢ` 的读数。⁸ 为数学方便，假设时钟**连续**而非离散"敲击"（一个离散时钟可视为连续时钟，读数有 ±½ 个 tick 的误差）。更精确地：`Cᵢ(t)` 是 t 的连续可微函数，仅在"重置"处出现孤立跳跃间断。则 `dCᵢ(t)/dt` 表示时钟 `Cᵢ` 在时刻 t 的运行速率。

⁸ 我们假设牛顿时空。如果时钟的相对运动或引力效应不可忽略，则 `Cᵢ(t)` 必须从实际读数通过"从固有时到所选时间坐标的变换"推得。

要让 `Cᵢ` 是真正的物理时钟，它必须**以接近正确的速率运行**——即 `dCᵢ(t)/dt ≈ 1`。我们假设：

> **PC1.** 存在常数 `κ ≪ 1`，使得对所有 i 与 t：`|dCᵢ(t)/dt − 1| < κ`。

典型晶振控制时钟有 `κ ≤ 10⁻⁶`。

仅各时钟独立地以接近正确速率运行还不够——它们必须被**同步**，使得对所有 `i, j, t` 都有 `Cᵢ(t) ≈ Cⱼ(t)`。更精确地：必须存在足够小的常数 ε 使得：

> **PC2.** 对所有 i, j 与 t：`|Cᵢ(t) − Cⱼ(t)| < ε`。

如果把图 2 的纵向距离视为物理时间，则 PC2 表示**单条 tick line 的高度变化小于 ε**。

**两个不同时钟的速率不会完全相同**——它们将越走越远。我们必须设计算法使 PC2 始终成立。但先看 κ 与 ε 必须多小，才能避免异常行为。我们要保证相关物理事件集合 𝒮̃ 满足**强时钟条件**。我们假设时钟满足普通时钟条件——所以只需对 `a ↛ b` 但 `a ⇝ b` 的不同进程事件考虑强时钟条件。

设 μ 是这样一个数：若事件 a 在物理时刻 t 发生，另一进程中事件 b 满足 `a ⇝ b`，则 b 在物理时刻 `t + μ` 之后发生。换言之，μ **小于跨进程消息的最短传输时间**。我们总能取 μ 为进程间最短距离除以光速；视消息如何传输，μ 也可能远大于此值。

为避免异常行为，必须保证对任意 i, j, t：`Cⱼ(t + μ) − Cᵢ(t) > 0`。结合 PC1 与 PC2，可以把 κ 与 ε 的小度与 μ 的值联系起来。我们假设时钟被重置时**永远向前**调（向后会让 C1 失效）。PC1 蕴含 `Cᵢ(t + μ) − Cᵢ(t) > (1 − κ)μ`；用 PC2 可推出：若以下不等式成立，则 `Cⱼ(t + μ) − Cᵢ(t) > 0`：

> `ε / (1 − κ) ≤ μ`.

此式连同 PC1、PC2 一起意味着**异常行为不可能发生**。

我们现在描述使 PC2 成立的算法。设消息 m 在物理时刻 t 发出、t' 时收到，定义 `νₘ = t' − t` 为该消息的**总延迟**。这个延迟接收方并不知道；但接收方知道某个**最小延迟** `μₘ ≥ 0` 满足 `μₘ ≤ νₘ`。称 `ξₘ = νₘ − μₘ` 为该消息的**不可预测延迟**。

把 IR1、IR2 特化为物理时钟：

> **IR1'.** 对每个 i：若 Pᵢ 在时刻 t 没有接收消息，则 `Cᵢ` 在 t 处可微且 `dCᵢ(t)/dt > 0`。
> **IR2'.**
> (a) 若 Pᵢ 在时刻 t 发送消息 m，则 m 含时间戳 `Tₘ = Cᵢ(t)`。
> (b) 收到消息 m 在时刻 t' 时，Pⱼ 把 `Cⱼ(t')` 设为 `max(Cⱼ(t' − 0), Tₘ + μₘ)`。⁹

⁹ `Cⱼ(t' − 0) = lim_{δ→0⁺} Cⱼ(t' − δ)`。

虽然规则形式上以物理时间参数表述，**进程实际上只需知道自己的时钟读数与所收消息的时间戳**。为数学方便我们假设每个事件都发生在精确瞬间，且同一进程中不同事件发生在不同瞬间。**这些规则是 IR1 与 IR2 的特化**——所以时钟系统满足时钟条件。真实事件有有限持续时间这一事实，对实现并无困难——实现里唯一真正要操心的是**让离散 tick 足够频繁，以维持 C1**。

我们现在表明：**这一时钟同步算法可使 PC2 成立**。设系统的进程由有向图描述——从 Pᵢ 到 Pⱼ 的弧表示直接发送消息的通信线。称"每 τ 秒经过该弧发送一条消息"是指：对任意 t，Pᵢ 在 [t, t+τ] 间至少向 Pⱼ 发一条消息。**有向图的直径** d 是这样最小的数：对任意一对不同进程 Pᵢ、Pₖ，存在从 Pᵢ 到 Pₖ 的路径不超过 d 条弧。

> **定理。** 设强连通图的进程网络直径为 d、始终遵守 IR1' 与 IR2'。对任意消息 m，`μₘ ≤ μ`（某常数）；并且对所有 t > t₀：
> (a) PC1 成立；
> (b) 存在常数 τ 与 ξ，使每 τ 秒在每条弧上发送一条不可预测延迟小于 ξ 的消息。
> **则 PC2 成立**——`ε = d(2κτ + ξ)`——对所有 `t > t₀ + τd`；其中近似假设 `μ + ξ ≪ τ`。

定理的证明出乎意料地难，附录给出。物理时钟同步问题已有大量研究，参见 [4]。文献中的方法有助于估计消息延迟 `μₘ`、调整时钟频率 `dCᵢ/dt`（对允许调整的时钟）。**然而"时钟绝不能向后调"这一要求似乎让我们的情况与既往研究不同——我们相信本定理是新结果**。

## 结论

我们看到了"happened before"概念在分布式多进程系统中定义了一个**不变的事件偏序**。我们描述了一种把该偏序扩展为某种**任意全序**的算法，并展示了如何用此全序解决一个简单同步问题。后续论文将展示这一思路如何推广到任意同步问题。

**该算法定义的全序是有些任意的——若与系统用户感知到的顺序不一致，会带来异常行为**。这可以通过使用恰当同步的物理时钟来避免；定理给出了时钟可被同步到的程度。

在分布式系统中，**重要的是认识到事件发生的顺序只是一种偏序**。我们相信这一思想对理解任何多进程系统都有用——它应当帮助人们独立于解决问题所用机制去理解多进程的根本问题。

## 附录：定理的证明

对任意 i 与 t，定义 `Cᵢᵗ` 为这样一个时钟：在时刻 t 它被设为 `Cᵢ`，并以与 `Cᵢ` 相同的速率运行，但永不被重置。即：

> `Cᵢᵗ(t') = Cᵢ(t) + ∫ₜᵗ' (dCᵢ(s)/ds) ds`.   (1)

对所有 t' ≥ t。注意：

> `Cᵢ(t') ≥ Cᵢᵗ(t')`，对所有 t' ≥ t。   (2)

设 P₁ 在 t₁ 时发消息给 P₂，P₂ 在 t₂ 收到，不可预测延迟 ≤ ξ，t₀ ≤ t₁ ≤ t₂。则对所有 t ≥ t₂：

> `C₂(t) ≥ C₂(t₂) + (1 − κ)(t − t₂)`            （由 (1) 与 PC1）
> `   ≥ C₁ᵗ¹(t₁) + μₘ + (1 − κ)(t − t₂)`        （由 IR2'(b)）
> `   = C₁(t₁) + (1 − κ)(t − t₁) − [(t₂ − t₁) − μₘ] + κ(t₂ − t₁)`
> `   ≥ C₁(t₁) + (1 − κ)(t − t₁) − ξ`

故对所有 t ≥ t₂：

> `C₂(t) ≥ C₁(t₁) + (1 − κ)(t − t₁) − ξ`.        (3)

现假设对 i = 1, …, n 有 `tᵢ ≤ tᵢ' < tᵢ₊₁`，`t₀ ≤ t₁`；并在 `tᵢ'` 时 Pᵢ 向 P_{i+1} 发消息，在 `tᵢ₊₁` 被收到，不可预测延迟 < ξ。重复应用 (3)，对 t ≥ t_{n+1} 得：

> `C_{n+1}ᵗ(t) ≥ C₁(t₁') + (1 − κ)(t − t₁') − nξ`.   (4)

由 PC1、IR1'、IR2' 推出：

> `C₁(t₁') ≥ C₁(t₁) + (1 − κ)(t₁' − t₁)`.

与 (4) 合并并用 (2)：

> `C_{n+1}(t) ≥ C₁(t₁) + (1 − κ)(t − t₁) − nξ`，对 t ≥ t_{n+1}.   (5)

对任意两个进程 P 与 P'，可找到进程序列 P = P₀, P₁, …, P_{n+1} = P'（n ≤ d），从每个 Pᵢ 到 P_{i+1} 都有通信弧。由假设 (b) 可找到时刻 `tᵢ, tᵢ'`，满足 `tᵢ' − tᵢ ≤ τ`，`t_{i+1} − tᵢ' ≤ ν`，其中 `ν = μ + ξ`。因此对 t ≥ t₁ + d(τ + ν)，(5) 形式的不等式以 n ≤ d 成立。所以对任意 i, j 与 t、`t₁ > t₀` 与 `t ≥ t₁ + d(τ + ν)`：

> `Cᵢ(t) ≥ Cⱼ(t₁) + (1 − κ)(t − t₁) − dξ`.   (6)

设 m 是任意时戳为 `Tₘ` 的消息，t 时发出、t' 时收到。我们假装 m 拥有以恒定速率运行的时钟 `Cₘ`，使得 `Cₘ(t) = Tₘ`、`Cₘ(t') = Tₘ + μₘ`。则 `μₘ ≤ t' − t` 蕴含 `dCₘ/dt ≤ 1`。规则 IR2'(b) 不过是把 `Cⱼ(t')` 设为 `max(Cⱼ(t' − 0), Cₘ(t'))`。**因此时钟只在被设为另一个时钟值时才被重置**。

对任意 `t_x ≥ t₀ + μ/(1 − κ)`，令 `Cₓ` 为在时刻 `t_x` 取最大值的时钟。由于所有时钟运行速率小于 `1 + κ`，对所有 i 与所有 `t ≥ t_x`：

> `Cᵢ(t) ≤ Cₓ(t_x) + (1 + κ)(t − t_x)`.   (7)

考虑两种情形：(i) `Cₓ` 是某进程 P_q 的时钟 `C_q`；(ii) `Cₓ` 是某条由 P_q 在时刻 t₁ 发出的消息的时钟 `Cₘ`。

情形 (i)：(7) 直接变为

> `Cᵢ(t) ≤ C_q(t_x) + (1 + κ)(t − t_x)`.   (8i)

情形 (ii)：`Cₘ(t_x) = C_q(t₁)` 且 `dCₘ/dt ≤ 1`，所以

> `Cₓ(t_x) ≤ C_q(t₁) + (t_x − t₁)`.

(7) 给出

> `Cᵢ(t) ≤ C_q(t₁) + (1 + κ)(t − t₁)`.   (8ii)

由于 `t_x ≥ t₀ + μ/(1 − κ)`：

> `C_q(t_x − μ/(1 − κ)) ≤ C_q(t_x) − μ`            （由 PC1）
> `         ≤ Cₘ(t_x) − μ`                          （由 m 的选择）
> `         ≤ Cₘ(t_x) − (t_x − t₁) μₘ/νₘ`           （μₘ ≤ μ, t_x − t₁ ≤ νₘ）
> `         = Tₘ`                                    （由 Cₘ 的定义）
> `         = C_q(t₁)`                              （由 IR2'(a)）

因此 `C_q(t_x − μ/(1 − κ)) ≤ C_q(t₁)`，故 `t_x − t₁ ≤ μ/(1 − κ)`，因此 `t₁ ≥ t₀`。

在情形 (i) 中令 `t₁ = t_x`，并合并 (8i) 与 (8ii)，对任意 t、t_x（`t ≥ t_x ≥ t₀ + μ/(1 − κ)`）存在进程 P_q 与 t₁ 满足 `t_x − μ/(1 − κ) ≤ t₁ ≤ t_x`，对所有 i：

> `Cᵢ(t) ≤ C_q(t₁) + (1 + κ)(t − t₁)`.   (9)

取 `t ≥ t_x + d(τ + ν)`，合并 (6) 与 (9)：存在 t₁ 与进程 P_q，使对所有 i：

> `C_q(t₁) + (1 − κ)(t − t₁) − dξ ≤ Cᵢ(t) ≤ C_q(t₁) + (1 + κ)(t − t₁)`.   (10)

令 `t = t_x + d(τ + ν)`：

> `d(τ + ν) ≤ t − t₁ ≤ d(τ + ν) + μ/(1 − κ)`.

合并 (10)：

> `C_q(t₁) + (t − t₁) − κd(τ + ν) − dξ ≤ Cᵢ(t) ≤ C_q(t₁) + (t − t₁) + κ[d(τ + ν) + μ/(1 − κ)]`.   (11)

利用 `κ ≪ 1` 与 `μ ≤ ν ≪ τ`，把 (11) 重写为如下近似：

> `C_q(t₁) + (t − t₁) − d(κτ + ξ) ⪅ Cᵢ(t) ⪅ C_q(t₁) + (t − t₁) + dκτ`.   (12)

由于这对所有 i 成立：

> `|Cᵢ(t) − Cⱼ(t)| ⪅ d(2κτ + ξ)`，对所有 `t > t₀ + τd`。
>
> ∎

**注：** 若 `μ + ξ ≪ τ` 不成立，关系 (11) 给出 `|Cᵢ(t) − Cⱼ(t)|` 的精确上界。证明的检视也提示了**快速初始化时钟、或在它们因故失同步时重新同步的简便方法**：每个进程发送一条会被中继到其他每个进程的消息——任意进程都可发起此过程；同步在不到 `2d(τ + ν)` 秒内完成（假设每条消息不可预测延迟小于 ξ）。
