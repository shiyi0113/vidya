# Software 2.0

**Andrej Karpathy · Medium · 2017 年 11 月 12 日**

> 原文：<https://karpathy.medium.com/software-2-0-a64152b37c35>

---

## 译者按

"编程"这件事正在被重新定义，这是把那个重新定义说清楚的文章。

---

我有时会看到有人把神经网络说成"只是机器学习工具箱里又一件工具"。它有它的优缺点，在这里那里能用一用，偶尔还能拿来赢 Kaggle 比赛。可惜，这种看法是彻底见树不见林。**神经网络不只是又一个分类器，它代表着我们开发软件方式的一次根本转变的开端。它是 Software 2.0。**

Software 1.0 那套"经典栈"我们都熟悉——用 Python、C++ 这样的语言写出来。它由程序员写给计算机的明确指令构成。每写一行代码，程序员就在程序空间里指定一个具有所期望行为的点。

> （配图：Software 1.0 — 程序员在程序空间中标识一个具体点）

相反，**Software 2.0 用一种远更抽象、远不那么人类友好的语言写就，例如神经网络的权重**。没有人会去写这种代码，因为权重很多（典型网络可能有上百万个），而且直接以权重编程相当困难（我试过）。

> （配图：Software 2.0 — 在权重空间中由优化定位出的一个区域）

我们的做法是：对一个期望程序的行为给出某种目标（例如"满足某个输入-输出样例数据集"或"赢得一盘围棋"），写一个粗略的代码骨架（即一个神经网络架构），它指定程序空间里待搜索的一个子集，然后用我们手头的算力在这个空间里搜索一个能用的程序。在神经网络的情形里，我们把搜索限制在程序空间的一个连续子集上，于是（多少有点出人意料地）搜索过程可以借助反向传播和随机梯度下降被做得高效。

> （配图：训练即把数据集"编译"为神经网络）

展开这个类比：在 Software 1.0 里，人工编写的源代码（比如一些 .cpp 文件）被编译成一个能做有用工作的二进制；在 Software 2.0 里，源代码绝大多数情况下由两部分组成——1）定义期望行为的数据集；2）给出代码粗略骨架、但许多细节（权重）待填的神经网络架构。**训练神经网络的过程，就是把数据集"编译"成那个二进制——也就是最终的神经网络**。在今天绝大多数实际应用中，神经网络架构和训练系统越来越标准化、商品化；于是大部分活跃的"软件开发"，是以"整理、扩充、揉打、清洗带标签数据集"的形式进行的。这从根本上改变了我们迭代软件所依据的编程范式——团队一分为二：2.0 程序员（数据标注者）编辑并扩充数据集，而少数几个 1.0 程序员维护并迭代外围的训练代码基础设施、分析、可视化与标注界面。

事实证明，现实世界的相当一部分问题都有这样的性质：**收集数据（更一般地，识别出一种期望的行为）远比显式地写出程序容易得多**。出于这一点，再加上后文要谈到的其他许多好处，我们正在见证整个产业的一次大迁移——大量 1.0 代码正在被移植成 2.0 代码。Software 1.0 在吞噬世界，而现在 AI（Software 2.0）正在吞噬 Software 本身。

## 正在发生的迁移

让我们简要看一些这次正在发生的迁移的具体例子。在以下每个领域，过去几年我们都看到了这样的进展：当我们放弃用显式代码处理某个复杂问题、改把代码迁到 2.0 栈上之后，效果就改善了。

**视觉识别（Visual Recognition）** 过去由人工设计的特征构成，最后再撒上一点机器学习（比如一个 SVM）。从那以后，我们通过获取大规模数据集（如 ImageNet）并在卷积神经网络架构空间里搜索，发现了远更强大的视觉特征。最近，我们甚至连架构本身都不信任自己手工去写，开始连架构一起搜索了。

**语音识别** 过去包含大量预处理、高斯混合模型和隐马尔可夫模型，今天则几乎完全由神经网络的东西组成。有一句相关、常被引用的玩笑话，据说来自 Fred Jelinek，1985 年："**每次我开除一个语言学家，我们语音识别系统的性能就上升一点**。"

**语音合成** 在历史上是用各种拼接机制来处理的，但今天最先进的模型是大型卷积网络（比如 WaveNet），它们直接产生原始音频信号输出。

**机器翻译** 过去主要采用基于短语的统计方法，如今神经网络正在迅速占据主导。我最喜欢的架构是在多语言环境下训练的——单个模型从任意源语言翻译到任意目标语言；以及在弱监督（甚或完全无监督）环境下训练的。

**游戏。** 显式手写的围棋程序已被开发了很长时间，但 AlphaGo Zero（一个看着棋盘原始状态、然后走一步棋的卷积网络）现在已成为遥遥领先最强的棋手。我预计我们将在别的领域看到非常类似的结果，例如 DOTA 2，或 StarCraft。

**数据库。** 在人工智能之外的更传统系统里，也开始出现迁移的早期迹象。例如，《The Case for Learned Index Structures》一文用神经网络替换了数据管理系统的核心组件，在速度上比为缓存优化过的 B 树高出多达 70%，同时在内存上节省了一个数量级。

你会注意到上面我贴的许多链接都涉及 Google 的工作。这是因为 Google 目前走在把自身大块大块重写为 Software 2.0 代码的最前沿。《One Model To Rule Them All》给出了这种重写可能长什么样的早期草图——各个单独领域里的统计能量被融合进对世界的一种统一理解中。

## Software 2.0 的好处

为什么我们要更倾向于把复杂程序移植成 Software 2.0？显然，一个简单的回答是：实践中它们效果更好。然而还有许多充分的理由让我们偏好这一栈。让我们看看 Software 2.0（想象一个卷积网络）相对于 Software 1.0（想象一份生产级别的 C++ 代码库）的几项好处。Software 2.0 是：

**计算上同质的（Computationally homogeneous）。** 一个典型神经网络，在一阶近似下，是只由两种运算交替夹成的三明治：矩阵乘法和在零处阈值化（ReLU）。把这一点与经典软件的指令集对比一下——后者要异质、复杂得多。因为你只需要为少数几个核心计算原语（如矩阵乘法）提供 Software 1.0 的实现，做各种正确性／性能保证就容易得多。

**容易做进硅片里。** 作为推论：既然神经网络的指令集相对很小，把这些网络以更贴近硅片的方式实现（如定制 ASIC、神经形态芯片等）就要容易得多。当**低功耗智能**遍布我们周围时，世界会改变。例如，小而便宜的芯片可以预装一个预训练的卷积网络、一个语音识别器和一个 WaveNet 语音合成网络，全集成在一个小小的"原始大脑"里，你可以把它贴到任何东西上。

**运行时间恒定。** 一个典型神经网络的每一次前向传递所耗的 FLOPS 完全相同。它没有因代码沿着某个庞杂 C++ 代码库走不同分支而产生的任何变动。当然，你也可以有动态计算图，但执行流通常仍受到显著约束。这样我们也几乎可以保证永远不会陷入意外的死循环。

**内存用量恒定。** 与上一条相关：到处都没有动态分配的内存，因此也很少有"换页到磁盘"或"需要在代码中追踪的内存泄漏"的可能。

**高度可移植。** 一连串矩阵乘法，相对经典二进制或脚本而言，要在任意计算配置上跑起来都容易得多。

**非常敏捷。** 假如你有一段 C++ 代码，有人让你把它做快一倍（必要时可以牺牲一些精度），把系统调到新规格上一点都不轻松。然而在 Software 2.0 里，我们可以把网络拿过来，砍掉一半通道，再训练一遍——好了，它就以正好两倍的速度运行，效果稍差一些。简直魔法。反过来，如果你恰好拿到了更多数据／算力，你只要加更多通道再训练一遍，就能立即让你的程序变得更好。

**模块能熔合为一个最优的整体。** 我们的软件常常被分解成通过公有函数、API 或端点通信的模块。然而，如果两个原本独立训练的 Software 2.0 模块要交互，我们可以轻易地对整体反向传播。想想这会多么惊人：如果你的浏览器能为更高效地加载网页，自动重新设计往下 10 层的底层系统指令；或者你导入的计算机视觉库（如 OpenCV）能在你具体的数据上自动调优。**在 2.0 里，这是默认行为**。

**它比你强。** 最后，也是最重要的一条：在很大一部分有价值的垂直领域，神经网络是一段比你我能写出来的任何东西都更好的代码。眼下至少包括所有与图像／视频、声音／语音相关的领域。

## Software 2.0 的局限

2.0 栈也有它自己的劣势。优化结束后，我们得到的是一个能跑得不错、却很难说清它为什么这样跑的大网络。在许多应用领域，我们会被置于一个选择面前——要一个我们理解的、准确率 90% 的模型，还是要一个我们不理解的、准确率 99% 的模型？

2.0 栈可能以不直观、令人难堪的方式失败——更糟的是，它们可能"无声地失败"，例如悄悄地把训练数据里的偏见吸收进来；当模型规模动辄数以百万计时，要恰当地分析与检查这种失败极其困难。

最后，这一栈的某些独特性质我们还在发现之中。例如，对抗样本与对抗攻击的存在凸显了这一栈不直观的本性。

## 在 2.0 栈里编程

Software 1.0 是我们写的代码。Software 2.0 是由基于评估准则（如"把这份训练数据分类对"）的优化所写出的代码。**任何这样的场景——程序本身并不显然，但可以反复评估其表现（如：你把若干图像分类对了吗？你赢得围棋比赛了吗？）——都可能经历这一迁移**，因为优化所能找到的代码，远远好过人能写出来的。

我们透过什么样的视角看趋势，是有分别的。如果你把 Software 2.0 看作一种新生的、正在涌现的编程范式，而不是简单地把神经网络当成机器学习这门技术里"还不错的分类器"，那么外推下去的种种就变得显而易见——也就能看清，还有多少工作要做。

具体来说，我们已经积累出大量协助人类写 1.0 代码的工具：强大的 IDE，语法高亮、调试器、性能分析、跳到定义、git 集成等等。**在 2.0 栈里，编程是通过积累、揉打、清洗数据集来完成的**。例如，当网络在某些困难或罕见的样例上失败时，我们不是通过写代码去修这些预测，而是通过加入更多带标注的此类样例。**谁会去做第一款 Software 2.0 IDE**——能协助你完成积累、可视化、清洗、标注、寻源数据集的全部工作流？也许它会基于逐样本损失，把网络怀疑被错标的图像浮上来；或者用预测作为种子辅助标注；或者基于网络预测的不确定性，建议哪些样例值得去标。

类似地，Github 是 Software 1.0 代码非常成功的家。**有没有一个 Software 2.0 Github 的位置？** 在这种情形下，仓库就是数据集，提交则是对标签的添加与编辑。

传统的包管理器与相关服务基础设施——pip、conda、docker 等等——帮我们更容易地部署与组合二进制。**我们如何有效地部署、共享、导入并使用 Software 2.0 的二进制？神经网络的 conda 等价物是什么？**

短期内，**Software 2.0 将在以下领域日益普及：可重复评估既可行又便宜、且算法本身难以显式设计**。考虑如何让整个软件开发生态系统适应这种新的编程范式，会有许多令人兴奋的机会。而从长期看，这一范式的前途光明，因为越来越清楚的一件事是：**当我们开发出 AGI 时，它一定是用 Software 2.0 写就的**。
