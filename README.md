# vidya

个人的认知工程项目。把计算机科学中那些奠基性的论文、演讲、笔记读透，从中提取可复用的思维框架，再打包成 Agent 可以调用的 skill。

名字取自梵语 **vidyā**（विद्या）——不是一般的"知识"，是**直接看见**。它的反面 avidyā 也不等于无知，而是看不清结构。这个项目对抗的就是 avidyā：不要二手解读，不要读书笔记式的复述，要看见结构本身。

## 用意

聪明人花几十年想清楚，再用一篇文章或一场演讲极致压缩出来的东西，是这个世界上密度最高的认知资产。读它们一遍，胜过读一百篇二手解读。

但读了不等于内化。真正改变思考方式的，是脑子里多了**一组可以反复使用的思维工具**——通常以提问的形式出现，每个都能切开一种常见的混淆：

- "Simple made Easy，还是 Complex made Simple？"（Hickey）
- "加人、加模块、加功能——加的是哪种痛？"（Brooks）
- "这段代码背后，我持有什么理论？"（Naur）
- "如果这里非变不可，第一刀落在哪？"（Parnas）

这些工具一旦在脑子里成形，就再也看不见旧的混淆。skill 把它们从"偶尔想起来"固化成"Agent 稳定调用"。

## 两个部件

**canon 是水源。** 经典文章的中文版，每篇附一段独立判断——不是摘要，是"它独特在哪里、哪里被高估、值不值得反复回来翻"。判断要承担责任，摘要只是复述。

**skills 是水管。** 把从 canon 里读出来的判断、方法、检查清单，重新组织成 Agent 可以调用的形式。每个 skill 独立目录，`SKILL.md` 是单一事实来源。形状随 skill 自己长，不预设模板（见下面"不做什么"）。

```
vidya/
├── canon/           # 经典文章中文版 + 独立判断
└── skills/          # 可复用的 Agent skills
    └── <skill-name>/
        ├── SKILL.md       # 单一事实来源
        ├── references/    # 可选
        ├── scripts/       # 可选
        └── assets/        # 可选
```

## 受众

主要给未来的我，其次给加载 skill 的 Agent。不为陌生人写橱窗——所以行文跳跃、术语不解释、判断不缓和。

## 规则

每条规则都是**反默认行为的约束**——存在是因为没有它就会滑向某种失败模式。

**canon 的判断段不是摘要。** 只回答"它独特在哪里、哪里被高估、值不值得反复翻"。防的是把仓库变成读书笔记——笔记复述，判断承担。

**skill 必须有清晰的非对称性才入库。** 默认拒绝。门槛是：能说出它对应的**核心非对称**（区分什么与什么）、**触发情境**（什么时候这个区分会绊倒人）、**默认失败模式**（不调用 skill 的人会怎么搞错）。说不出来，就先留在 canon 的判断里，不要急着升格。防的是 skill 泛滥——一年后有 80 个浅 skill 比有 8 个深 skill 糟糕得多。

**SKILL.md 是单一事实来源。** 同一个 skill 的所有约定、触发条件、执行步骤都进 SKILL.md，不散落到 references 或脚注。防的是真相分裂——分裂后维护成本指数上升。

**不存平台相关的元数据。** 没有特定 Agent 框架的配置文件混进核心仓库。防的是 vendor lock-in——这些 skill 的生命周期应该比任何具体 Agent 平台更长。

## 不做什么

- **不做二手解读。** 不收博客对论文的转述、不收 listicle、不收"程序员必读的十本书"。
- **不做摘要。** 见上面规则一。
- **不套模板做 skill。** 每个 skill 顺着它对应文章自己的形态生长。Naur 的"理论建构"和 Lamport 的"happens-before"长出的 skill 在结构上没理由相似。
- **不收藏式扩张。** canon 宁缺毋滥，skill 更严。
